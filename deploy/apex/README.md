# APEX droplet deployment (paper)

Exact config running on APEX (2026-10-01). Code = this branch.

## One-command deploy / update

On the droplet: `curl -fsSL https://raw.githubusercontent.com/derekduenas/lip-maker/apex/patches-1-17/deploy/apex/deploy.sh -o /tmp/deploy.sh && sudo bash /tmp/deploy.sh`

It backs up the code tree, env file and units to /var/backups/lip-maker/<timestamp>, swaps in the branch, builds the venv, applies the checklist below (removes LIP_BANKROLL, forces paper, carries the prod read key over from the old repo .env, installs the polkit rule), enables both services at boot (Restart=always, no start-rate limit), starts them and verifies /status. After the /status check it also prints, for information only (neither can fail the deploy), `tools/verify_ws_frames.py --newest 1` on the newest frame recording when recordings exist (`LIP_RECORD_DIR` from the env file or drop-ins, default /var/lib/lip-maker/recordings; right after a restart that file holds only the first seconds) and the readiness report's `OVERALL:` line. Rollback: `sudo bash /opt/lip-maker/deploy/apex/deploy.sh --rollback /var/backups/lip-maker/<timestamp>`.

## Before deploying this branch

1. Delete `LIP_BANKROLL` from /etc/lip-maker/lip-maker.env if it is there (the EnvironmentFile overrides policy.conf's pinned `LIP_BANKROLL=1500`; older copies set 5000): `sudo sed -i '/^LIP_BANKROLL=/d' /etc/lip-maker/lip-maker.env`.
2. Check that `KALSHI_PROD_READ_KEY_ID` and `KALSHI_PROD_READ_KEY_PATH` are in /etc/lip-maker/lip-maker.env, not only in /opt/lip-maker/.env: the repo .env is no longer auto-loaded, and without them the paper engine silently read DEMO books. It now logs a `!!!` WARNING at startup and reports `book_source_warning` in /status when it falls back; after the restart check `curl -s 127.0.0.1:8765/status | jq '.data_source, .book_source_warning'` shows `"production-books"` and `null`. The key file must be readable by user lip.
3. Install the polkit rule below (watchdog stop fallback when the kill file cannot be written) and check `sudo -u lip systemctl stop lip-unattended` works without a password prompt.
4. Expect smaller quotes: every order is capped at $25 (the session's $100 single-fill cap is lowered to `LIP_MARKET_INV_CAP_USD=25`), and lower PM US estimates: a PM US pool is divided across the markets sharing its program and period (`LIP_PMUS_POOL_SPLIT=members`, the default).
5. On the first start of this branch /var/lib/lip-maker/engine_state.json does not exist yet: the engine logs "no engine state ... starting flat" and creates it. That is expected. (A file that exists but cannot be read latches the engine kill until it is moved aside.)
6. Resetting kills: engine kill latch saved in the state file: `cd /opt/lip-maker && sudo -u lip .venv/bin/python -m mm.unattended --reset-kill` then `sudo systemctl restart lip-unattended`. Watchdog trip: `cd /opt/lip-maker && sudo -u lip .venv/bin/python -m mm.safety.lip_watchdog --reset` then restart lip-unattended (or `systemctl start` if the watchdog stopped it). Both, if both latched.
7. Behaviour to expect: Kalshi positions past close are settled from read-only `GET /markets/{ticker}` on the background refresh when the websocket missed it; PM US positions past close are checked against the public gateway's settlement endpoint, and one still unsettled 24 h past close (`LIP_PMUS_UNSETTLED_RELEASE_S`) is released from budgets and booked as a full loss of its cost (listed in /status `unresolved_positions`; this can move the daily P&L the watchdog checks). A position unsettled 24 h past close raises a WARNING alert. The clock-skew guard pulls only after 3 consecutive frames more than 5 s late (`LIP_CLOCK_SKEW_N`, `LIP_CLOCK_SKEW_LIMIT_S`). The watchdog's daily P&L now uses the engine's `daily_mtm_pnl_usd`.

- lip-unattended.service: deploy/lip-unattended.service + drop-ins in lip-unattended.service.d/ (override.conf = venv python; policy.conf = paper policy knobs, patches 5-16).
- Paper is forced three ways: `LIP_FORCE_PAPER=1` (resolve_mode refuses anything but paper while it is set), `Environment=` lines in the base unit and both drop-ins, and an `/usr/bin/env LIP_FORCE_PAPER=1 LIP_PAPER=true` prefix on ExecStart. override.conf replaces the base ExecStart, so it repeats that prefix; /etc/lip-maker/lip-maker.env (EnvironmentFile) overrides `Environment=` lines but not the env(1) prefix.

- Engine state: positions, fill/fee aggregates, rolled periods, cooldowns and an internal kill latch persist in `LIP_STATE_FILE` (default /var/lib/lip-maker/engine_state.json) across restarts. An unreadable state file latches the engine kill until it is moved aside. To clear an engine kill latch that was persisted there (positions kept): `cd /opt/lip-maker && sudo -u lip .venv/bin/python -m mm.unattended --reset-kill`, then restart lip-unattended. This is separate from the watchdog's `--reset`.
- Manual tool runs (tools/*.py, ad hoc scripts using execution/kalshi_auth.KalshiClient): the repo .env is no longer loaded on import. Credentials come from the environment; set `LIP_LOAD_DOTENV=1` to have the client read the repo .env (it never sets LIP_* keys). The services do not set it.
- Python: requirements.txt was pinned on Python 3.13 (the Dockerfile uses python:3.13-slim); every pin also has a 3.12 wheel. Which Python the APEX venv (/opt/lip-maker/.venv, created by the command-box install noted in override.conf) runs is not recorded in this repo; deploy/droplet/setup.sh targets Ubuntu 24.04, whose python3 is 3.12. Check with `/opt/lip-maker/.venv/bin/python --version`.
- lip-watchdog.service (patch 17): independent kill switch, `python -m mm.safety.lip_watchdog`, user lip, `Restart=always` with no start-rate limit. Settings: watchdog.env.example (append to /etc/lip-maker/lip-maker.env; secrets stay out of the repo).
- Kill flag: /var/lib/lip-maker/KILL (LIP_KILL_FILE). The engine checks it on a timer that runs independently of market-data frames, so a stalled feed does not stop the check, and latches external_kill (cancels all quotes). (At cd8af63 it was only checked inside the frame callback, at most once per second while frames arrived.)
- Kill file unwritable: the watchdog runs `LIP_WD_STOP_CMD` (default `systemctl stop lip-unattended`) every tick until the file lands, with TRIP alerts. User lip cannot stop a system unit by default. Install this polkit rule (it works with the unit's NoNewPrivileges=true; a sudoers entry would not):

  ```
  // /etc/polkit-1/rules.d/50-lip-watchdog.rules
  polkit.addRule(function(action, subject) {
      if (action.id == "org.freedesktop.systemd1.manage-units" &&
          action.lookup("unit") == "lip-unattended.service" &&
          (action.lookup("verb") == "stop" || action.lookup("verb") == "restart") &&
          subject.user == "lip") {
          return polkit.Result.YES;
      }
  });
  ```
  Check: `sudo -u lip systemctl stop lip-unattended` stops it without a password prompt.
- Live cancel-all arming: real Kalshi API writes only when the watchdog's own env has `LIP_WD_LIVE_ARMED=true` and `LIP_PAPER` not true. Given that, it cancels when /status reports live_armed, or the engine was ever seen live (persisted in watchdog_state.json until `--reset`; a corrupt state file counts as seen live), or /status is unreachable (dead/hung engine). Engine reporting live while the watchdog is not armed is a TRIP: "engine live but watchdog unarmed". The engine gets LIP_PAPER from its drop-in and the watchdog from the env file; keep them in step.
- Cancel scope: the Kalshi account is shared with the Weather engine. `LIP_WD_CANCEL_SCOPE=ours` (default) cancels only orders whose client_order_id starts with `LIP_WD_COID_PREFIX` (default `LIP-`); `all` cancels every resting order on the account. Cancels use `DELETE /portfolio/events/orders/{id}` with each order's market_ticker and exchange_index, then re-list to verify.
- Watchdog self-failure: a tick exception alerts; `LIP_WD_TICK_FAILS` (3) in a row latches the watchdog (watchdog_tick_failing) and writes the kill file.
- Reset after a trip: `cd /opt/lip-maker && sudo -u lip .venv/bin/python -m mm.safety.lip_watchdog --reset && sudo systemctl restart lip-unattended`. Reset removes the kill file and clears the latch and the persisted engine-seen-live flag. If the engine was stopped by LIP_WD_STOP_CMD, `systemctl start lip-unattended` instead of restart.
- Health: /var/lib/lip-maker/watchdog_health.json (includes config_armed, engine_seen_live, inventory basis); watchdog alerts: /var/lib/lip-maker/alerts.log (JSON lines), alert.json. Engine alerts (kill latches, unsettled positions; monitor.alerts text lines `ISO  LEVEL  source  message`): /var/lib/lip-maker/alerts-engine.log (`LIP_ENGINE_ALERT_LOG` overrides; if /var/lib/lip-maker is missing or not writable they fall back to <repo>/logs/alerts.log), also in the journal.
- Scheduled-event calendar (off by default): set `LIP_EVENT_CALENDAR_FILE` (e.g. `/etc/lip-maker/event_calendar.json`, readable by lip) to pull and refuse quotes on markets whose series/ticker starts with an event's prefix, from `at - pre_minutes` to `at + post_minutes` (status/pulls reason `scheduled_event`). Start from event_calendar.example.json: its entries are EXAMPLE placeholders dated 2099, not real release dates; the operator must enter and maintain real, verified times. Unset: no pulls (logged once). Set but missing/invalid: every market is blocked (`scheduled_event_calendar_error`, CRITICAL alert) until fixed. The file is re-read within 60 s of a change.
- Phase 4 measurement (paper estimates): /status `markout_horizons` (fill markouts at 5 s / 30 s / 2 min / 10 min / 1 h and settlement, vs book mark and external fair value, by venue and bucket; pending checks bounded by `LIP_MARKOUT_MAX_PENDING`, 5000 fills) and `pnl_attribution` (spread capture, adverse selection, inventory/settlement MTM, estimated rewards per venue, rebates, fees; sums to `pnl_usd`; also in the daily summary).

## Weather fair value (paper)

What it does. For Kalshi daily HIGH temperature markets (series prefix `KXHIGH`) the engine prices its own fair value. Calibration (`LIP_FV_CALIB_ENABLE`, on whenever `LIP_FV_ENABLE=1`) records every value against the book and scores it at settlement, whether or not it quotes. With `LIP_FV_QUOTE_ENABLE=1` it also drives PAPER quotes: a side is rested only if it does not pay more than `LIP_FV_MAX_GIVEUP_CENTS` above fair value (edge = FV - YES bid, or (100 - FV) - NO bid) and its expected $/day (edge x expected fills/day from the selector's fill model + that side's LIP reward - maker fees) is positive; a side resting alone earns its one-sided snapshot share (Kalshi excludes a snapshot whose other side does not reach target), not half the two-sided reward. Selection credits the model's view only as edge versus the book mid (FV - mid for a YES bid, mid - FV for a NO bid; both sides resting cancel out) and only once the calibration verdict is `model_better_than_book`; until then the model only withholds negative-edge sides. Every other family keeps the Patch 16 disagreement guard unchanged. A model value is used only in paper mode (FV quoting, the Patch 16 guard and fv markouts ignore it outside paper; the guard also ignores it while FV quoting is off for its family), in code (`RunLoop._fv_quote_row`, `RunLoop._model_row_allowed`). The screen feeds KXHIGH markets early (under `LIP_FV_MIN_HOURS_TO_CLOSE`) only in paper.

Data source terms: the Open-Meteo free API is for non-commercial use only (https://open-meteo.com/en/terms: "Integrating our service into commercial products" is commercial use; commercial users subscribe to an API plan). This is paper data collection; the terms must be reviewed (and a plan bought if needed) before any live use of this model.

Model (mm/unattended/fv_weather.py, background fair-value thread only, never on the tick path):
- Settlement: the NWS Daily Climate Report (CLI) maximum, whole degrees F, for the day in local STANDARD time (1:00 AM to 12:59 AM local during DST). Sources: Kalshi contract terms (kalshi-public-docs.s3.amazonaws.com/contract_terms/NHIGH.pdf, AUSHIGH.pdf, MIAHIGH.pdf; KalshiEX CFTC filings for Chicago Midway, Denver, Philadelphia) and https://help.kalshi.com/en/articles/13823837-weather-markets. Buckets come from each market's `strike_type` / `floor_strike` / `cap_strike` (between is inclusive, greater/less strict), never from the ticker.
- Supported stations: KXHIGHNY Central Park (KNYC), KXHIGHCHI Chicago Midway (KMDW), KXHIGHAUS Austin Bergstrom (KAUS), KXHIGHDEN Denver Intl (KDEN), KXHIGHPHIL Philadelphia (KPHL), KXHIGHMIA Miami (KMIA). Not priced (station not verified): KXHIGHLAX and the KXHIGHT* series. Source URLs per station are in `fv_weather.STATIONS`.
- Forecast: `GET https://ensemble-api.open-meteo.com/v1/ensemble?latitude=..&longitude=..&hourly=temperature_2m&models=gfs025,ecmwf_ifs025&temperature_unit=fahrenheit&timezone=GMT&start_date=D&end_date=D+1` (free, no key), each member's max over the window. Model ids are those the ensemble docs list (https://open-meteo.com/en/docs/ensemble-api, checked 2026-10-01: GFS Ensemble 0.25 deg `gfs025`, 31 members; IFS 0.25 deg `ecmwf_ifs025`, 51 members; both natively 3-hourly). The docs say "all data is interpolated to a 1-hourly time-step resolution" and document no ensemble parameter for native output, so hourly member values between the 3-hourly steps are interpolated and each member's max under-reads the afternoon peak: that warm bias is what the per-station `bias_f` is for, and it is not set by hand (default 0) but fitted (below).
- Same day: `GET https://api.weather.gov/stations/<ICAO>/observations?start=<window start>` (User-Agent `LIP_FV_NWS_USER_AGENT`). Values (usually degC with 0.1 precision) are converted to F, rounded to 0.01 F, then the max so far is rounded half up to the whole degree the CLI prints (75.92 F -> 76). Forecast mass below that value is placed on it, except `LIP_FV_WX_OBS_SLIP` (0.1) of it placed one degree lower (ASOS -> CLI difference). Once the window has started and no observation is available (fetch failure, or none in the window yet), the market has NO fair value (fail closed).
- Unfitted defaults are deliberately wide: spread inflation 1.4, Gaussian kernel sd 1.75 F, bias 0; whole-degree rounding, probabilities clipped to [0.01, 0.99], confidence lowered for long leads and few members.
- Fail closed: any fetch/parse failure, no observation on a started day, too few members, missing strike fields, an unreadable parameter file or confidence below `LIP_FV_MIN_CONF` means no fair value: the market is not quoted under FV rules, and one that was selected only because of its fair value (it closes inside the 48 h `LIP_MIN_HOURS_TO_CLOSE` gate) is pulled with reason `fv_unavailable`.

Fitting the parameters. Each settled sample (market range, outcome, fair value, mid, and the model's member-max summary: mean, sd, member count, observation floor) is appended by the engine to `LIP_FV_CALIB_SAMPLES_FILE` [/var/lib/lip-maker/fv_calib_samples.jsonl] (a few hundred bytes per settled market and lead bucket; not rotated). Fit per-station bias and inflation by maximum likelihood:

`sudo -u lip /opt/lip-maker/.venv/bin/python /opt/lip-maker/tools/fit_fv_weather.py` (report only), then `... --out /etc/lip-maker/fv_wx_params.json`, set `LIP_FV_WX_PARAMS_FILE=/etc/lip-maker/fv_wx_params.json` and restart. A station needs `--min-events` (30) settled city-days or it is not written; with none the tool writes nothing (exit 2). The fit is in-sample: judge it on `fv_calibration` afterwards.

Knobs (policy.conf turns it on for paper; code defaults in brackets):
- `LIP_FV_QUOTE_ENABLE=1` [0]: FV-driven quoting on. Needs `LIP_FV_ENABLE=1` (the background cache).
- `LIP_FV_CALIB_ENABLE=1` [1 when `LIP_FV_ENABLE=1`]: price the model families and record calibration samples even with quoting off (changes no quote).
- `LIP_FV_QUOTE_FAMILIES=KXHIGH` [KXHIGH]: series prefixes (model families, for quoting and calibration).
- `LIP_FV_MIN_CONF=0.6` [0.6]: shared with the Polymarket match confidence; also the calibration headline cut.
- `LIP_FV_MIN_HOURS_TO_CLOSE=24` [unset = global]: minimum hours to close for an FV family market WITH a usable fair value (daily highs close 11:59 PM local on the day, inside the 48 h global gate). The 6 h event window (`LIP_EVENT_WINDOW_HOURS`, anchored at 00:00 ET of the ticker date) still stops quoting at 18:00 ET the day before; the close cutoff and every other gate are unchanged.
- `LIP_FV_MAX_GIVEUP_CENTS=0` [0]: never pay up versus FV for rewards.
- `LIP_FV_LONGSHOT_TILT=0` [0, off]: cents of edge removed from YES bids below 15c (favourite-longshot bias on Kalshi: "Makers and Takers: The Economics of the Kalshi Prediction Market", MPRA 126350, https://ideas.repec.org/p/pra/mprapa/126350.html).
- Model: `LIP_FV_WX_MODELS` [gfs025,ecmwf_ifs025], `LIP_FV_WX_KERNEL_SD` [1.75], `LIP_FV_WX_PARAMS_FILE` [unset: bias 0, inflation 1.4 for every station; JSON `{"KXHIGHNY": {"bias_f": 0.0, "inflation": 1.4, "kernel_sd_f": 1.75}}`, written by tools/fit_fv_weather.py], `LIP_FV_WX_OBS_SLIP` [0.1, max 0.5], `LIP_FV_WX_MIN_MEMBERS` [10], `LIP_FV_WX_MAX_LEAD_H` [168], `LIP_FV_WX_ENS_TTL_S` [1800], `LIP_FV_WX_OBS_TTL_S` [300], `LIP_FV_WX_TIMEOUT_S` [15], `LIP_FV_WX_CONF_HORIZON_H` [240], `LIP_FV_WX_FULL_MEMBERS` [40]. (`LIP_FV_WX_OBS_MARGIN_F` is gone.)
- Calibration: `LIP_FV_CALIB_EVERY_S` [30], `LIP_FV_CALIB_MIN_MARKETS` [200], `LIP_FV_CALIB_MIN_EVENTS` [40], `LIP_FV_CALIB_SAMPLES_FILE` [/var/lib/lip-maker/fv_calib_samples.jsonl]. (`LIP_FV_CALIB_MIN_N` is gone.)

What to watch in /status:
- `fair_value.fv_quote`: `driving` (markets quoted on FV now), `admitted_on_fv`, `counters` (`edge_withheld_*`, `ev_withheld_*`, `unavailable`), `fair_value.weather_high` (fetches, errors, `no_obs`, last_error). `pulls.fv_negative_edge` / `pulls.fv_unavailable`.
- `fv_calibration`: per market and lead bucket the first sample (Brier, log loss) and, kept separately, the first sample that had a two-sided book (model vs book mid: `paired_*`, `skill_vs_book`), with `paired_markets` (distinct markets with a paired sample). Per city-day event (`events`): when every bucket of the event is priced at the same moment and the buckets tile the line, the whole distribution (fair values normalised) is scored at settlement with the ranked probability score and the log score, against the book's (mids normalised; only when every bucket has a mid): `events.overall.rps_skill_vs_book`, `events.paired_events`. Samples with conf below `LIP_FV_MIN_CONF` are reported under `low_conf` only. `verdict` stays `insufficient_data` until 200 paired markets AND 40 paired events, then `model_better_than_book` only if the event RPS skill and the paired per-market Brier skill are both > 0. Aggregates from before this format show under `legacy` and never count. Sampling covers every fed KXHIGH market of a supported station, quoted or not, until its close: a market stays in the calibration watch (`watching_n`, persisted in the engine state file) after its program leaves the loop or the engine restarts, so the 0-12h / 12-24h lead buckets fill although FV-driven quotes stop at 24 h to close. Samples taken while the market is no longer fed have no book mid (model only, not paired). A market whose samples are still pending `LIP_FV_CALIB_BACKFILL_AFTER_S` (43200 s = 12 h) after close (its websocket determination was missed, e.g. while disconnected) is added after held positions to the read-only `GET /markets/{ticker}` settlement backfill, so its samples are scored.
- `curl -s 127.0.0.1:8765/status | jq '.fv_calibration.verdict, .fv_calibration.paired_markets, .fv_calibration.events.paired_events, .fv_calibration.events.overall, .fair_value.fv_quote.counters'`
- The readiness report's `fv_calibration` criterion needs the same: `paired_markets` >= 200 and `events.paired_events` >= 40 (flags `--min-fv-markets`, `--min-fv-events`), the engine's verdict `model_better_than_book`, and model paired Brier and event RPS below the book's.

Caveat: this model is unproven. The bias/inflation are not fitted until tools/fit_fv_weather.py has 30+ settled city-days per station, hourly forecast values under-read the true daily max, and the confidence score is a heuristic, not a probability. Until `fv_calibration` says `model_better_than_book` (per station too, not only overall), the model must not be trusted with real money, and nothing here is wired to live trading. Off switch for quoting: `LIP_FV_QUOTE_ENABLE=0` in policy.conf (or the env file), then restart; the Patch 16 guard then applies to KXHIGH again, and calibration keeps recording (`LIP_FV_CALIB_ENABLE=0` stops that too).

## Verify websocket frames against real captures (after deploy)

Several engine fixes were tested against documented, not captured, Kalshi frames: `sending_ts_ms` / `msg.ts_ms` (clock-skew guard), `market_lifecycle_v2` settlement, subscription-id merging, `ok`/`subscribed` seq. Once the engine has recorded for a while (`LIP_RECORD_ENABLE=1` in policy.conf; files rotate hourly), run on the droplet:

`sudo -u lip /opt/lip-maker/.venv/bin/python /opt/lip-maker/tools/verify_ws_frames.py --newest 3`

Read-only. It reads the newest N `frames-*.jsonl.gz` in /var/lib/lip-maker/recordings (`--dir`, or pass files/globs) and prints frame type counts, the share of book snapshots/deltas carrying `sending_ts_ms` / `msg.ts_ms`, recv-minus-exchange time p50/p95/p99/max per field and how often it exceeds the engine's `LIP_CLOCK_SKEW_LIMIT_S` (taken from `--skew-limit`, else the environment, else the installed lip-unattended drop-ins and /etc/lip-maker/lip-maker.env, else loop.py's default) plus how many times the guard would have pulled, settlement samples, sid-merge evidence and seq gaps. `--json` for machine-readable output. Exit 0 = every field the engine reads was seen; 1 = a field the engine depends on is absent from every recorded frame of that type (the corresponding fix is not doing anything on real data: investigate before trusting it); 2 = no recordings.

What the recorder shows: it stores every frame passed to RunLoop after `loop._dispatch_ws_message`. Book frames carry `seq: null` with the original kept as `ws_seq` (seq gaps per sid: snapshot gaps are the merge resyncs SidSequencer allows, delta gaps are real; `ok`/`unsubscribed` acks advance the sid's seq exactly as the engine does, so an update_subscription ack is not a gap). Raw `market_lifecycle_v2` messages (only for markets the engine follows: a program, a position, a calibration watch or pending calibration samples) and `subscribed`/`unsubscribed`/`ok` replies are recorded as `{"type": "ws_raw", "channel": ..., "msg": ...}` rows next to the derived `settlement` frames, serialised off the frame lock; a real gap the engine detects is recorded as a `seq_gap` ws_raw row before it reconnects (`seq.engine_gaps`). RunLoop and the replay bench ignore those rows and the tool unwraps them (`ws_raw_rows` in the output). `--min-age-s N` skips recordings opened less than N s ago; deploy.sh runs `--newest 1 --min-age-s 600` so it does not check the file the engine it just restarted opened. Recordings made by an engine before this change lack `ws_seq` and the raw rows: for those the tool prints a `note:` instead of a verdict and sid-merge evidence comes from book frames only.

## Go-live readiness report (read-only)

`sudo -u lip /opt/lip-maker/.venv/bin/python /opt/lip-maker/tools/readiness_report.py` (`--json` for machine output). It sends one GET to http://127.0.0.1:8765/status and reads the daily summary, /var/lib/lip-maker/engine_state.json, watchdog_health.json, watchdog_state.json and the alert logs; it writes nothing and does not touch LIP_PAPER / LIP_LIVE_ACK, the maker-only enforcement flags or LIP_WD_LIVE_ARMED. Each criterion prints PASS / FAIL / INSUFFICIENT (N/A when it does not apply); missing data is INSUFFICIENT, never PASS; overall READY only if every applicable criterion passes (exit 0 READY, 1 NOT READY, 2 INSUFFICIENT DATA). Criteria and defaults (all flags, see `--help` and the module docstring): >= 14 production-books paper days and no `book_source_warning`; >= 300 non-synthetic Kalshi fills; >= 100 settled positions; P&L excluding estimated rewards and rebates >= 0 (also prints the rewards share of P&L); 10-minute markout mean >= -0.5c/contract over >= 100 fills; no engine kill latch or watchdog trip in 7 days except operator tests (put the phrase `operator test` in the kill file / reason when drilling); if status reports `fv_calibration`: >= 200 paired distinct markets and >= 40 paired distinct city-day events, the engine's own verdict `model_better_than_book`, and model paired Brier and event RPS below the book's; daily loss limit not hit in the last 14 days (`--daily-loss-lookback-days`, or `--since`). READY is advisory: going live remains an explicit human decision behind the existing gates.

Data it cannot get from the engine today (so those criteria stay INSUFFICIENT until fixed or supplied):
- Days: the engine overwrites /var/lib/lip-maker/daily-summary with the current UTC day, and keeps one JSON line per UTC day (that day's last summary: day, data_source(s), fills, P&L, attribution) in /var/lib/lip-maker/daily-summary.history.jsonl, written on day roll, on shutdown (including `systemctl stop`/restart: the engine handles SIGTERM by cancelling its websocket driver at the next await and running its normal shutdown: final state save, recorder drain, calibration samples flush, summary history; exit 0) and every `LIP_SUMMARY_HISTORY_EVERY_S` (600 s; bounds the loss on a crash or SIGKILL), newest `LIP_SUMMARY_HISTORY_MAX` (400) days kept. The report reads it by default, so the 14-day criterion can pass after 14 production-books days of history. A day that saw any non-production source (`data_sources`) does not count. Dated copies (`--summary '/var/lib/lip-maker/summaries/*'`) and other history files (`--summary-history`) still count.
- Settled positions: the engine keeps lifetime counters that survive `LIP_SETTLED_KEEP_DAYS` (7) pruning: /status `settled_positions_n`, `settled_positions_by_venue`, `settled_total_usd` (realized settlement P&L: payout minus cost basis, fees excluded), persisted as `settled_lifetime` in engine_state.json. A state file written before the counters existed seeds them from its remaining settled rows (`settled_positions_lower_bound: true`); a short lower-bound count is INSUFFICIENT, not FAIL.
- Engine alerts (kill latches) are written to /var/lib/lip-maker/alerts-engine.log (or `LIP_ENGINE_ALERT_LOG`), which deploys do not move; the report reads it next to the watchdog's /var/lib/lip-maker/alerts.log. Engines before this change wrote /opt/lip-maker/logs/alerts.log inside the code tree (deploy.sh moves it to /opt/lip-maker.prev, and user lip could not create it in the root-owned tree); the report still reads /opt/lip-maker/logs/alerts.log and /opt/lip-maker.prev/logs/alerts.log, and older history is in /var/backups/lip-maker/<timestamp>/app/logs/alerts.log (pass it with `--alerts`).
- P&L attribution is cumulative over the engine state file's life, not a trailing window.


## Auto-recover for transient watchdog trips (2026-10-02)

The 2026-10-01/02 overnight outage was a false `heartbeat_missing` trip: the engine's heartbeat
write (truncate, then write) was read by the watchdog in between. It is fixed at the source
(atomic `os.replace` write; the watchdog re-reads an empty/partial file and falls back to its
mtime), and the watchdog can now clear transient latches by itself:

- `LIP_WD_AUTO_RECOVER=1` (code default off; on in watchdog.env.example). Only when every reason
  seen during the latch is transient: `heartbeat_missing`, `heartbeat_stale`, `status_unreachable`,
  `feed_no_frames`, `feed_stale`, `pmus_feed_stale`. Never when the watchdog's own config is armed live.
- After `LIP_WD_AUTO_RECOVER_HEALTHY_S` (300) of clean checks: removes the kill file and runs
  `LIP_WD_RESTART_CMD` (`systemctl restart lip-unattended`, needs the polkit rule above with the
  `restart` verb). If the restart fails the kill file is rewritten and the latch stays.
- Still failing `LIP_WD_AUTO_RESTART_AFTER_S` (600) after the trip: one engine restart (hung engine);
  the latch stays until the checks are clean.
- `LIP_WD_AUTO_RECOVER_GRACE_S` (180) after a watchdog restart, transient reasons are ignored.
- At most `LIP_WD_AUTO_RECOVER_MAX_PER_DAY` (3) restarts per UTC day, then it stays latched for a human.
- Status: `watchdog_health.json` -> `auto_recover`; alerts `auto_recover`, `auto_restart`,
  `auto_recover_failed`, `auto_budget` in alerts.log.
- Not covered: engine-internal kills (daily loss, disconnect >= LIP_DISCONNECT_KILL_S, state file)
  are persisted in engine_state.json and need `python -m mm.unattended --reset-kill`.

## Kalshi paper fill fix (2026-10-04)
Why: in 40 h after the Oct 2 restart there were 0 Kalshi paper fills and 968k quote pulls, 99.99% of them clock_skew. The process subscribed to about 1,395 books to quote 17. It was CPU-bound, so Kalshi frames arrived 5-10 s late. The 5 s skew guard then cleared on a single clean frame, and every clear ran a full re-selection, which kept the process CPU-bound. Quotes also sat 1-2 ticks behind the touch in markets that rarely trade. Knobs (policy.conf):
- Subscriptions: `LIP_WS_SUB_MAX` (150; 0 = every fed program, the old behaviour), `LIP_WS_SUB_CORE` (60 top-ranked), `LIP_WS_SUB_ACTIVE` (20 most traded, from read-only `GET /markets/trades` counts every `LIP_ACTIVITY_REFRESH_S`=1800 s over the `LIP_ACTIVITY_PROBE_N`=60 highest-volume candidates), `LIP_WS_SUB_ROTATE` (40 rotating every `LIP_WS_ROTATE_S`=120 s). Markets with resting quotes, held positions or an active cooldown are always kept. A fed program whose book is not subscribed is `inactive`: it is left out of selection and books-ready until its next snapshot. `LIP_WS_CHANNELS` defaults to `orderbook_delta,trade`. The `ticker` channel was never read.
- Clock-skew guard: `LIP_CLOCK_SKEW_CLEAR_S` (15) of clean frames, with no late frame in between, before it clears. 0 restores the old one-clean-frame rule.
- Paper simulator: `LIP_SIM_BOOK_DEPLETION` (queue-ahead is cut to the displayed size at our price; a cut that a print's trade message later explains is not taken out twice) and `LIP_SIM_KEEP_QUEUE` (a same-price re-quote with the same or smaller size keeps queue position).
- Placement: `LIP_JOIN_TOUCH`=1 and `LIP_JOIN_MAX_TICKS`=2. Each Kalshi side moves from the LIP reference (the level holding Target/5) up toward its best bid by at most N ticks. It never goes above the touch and never reaches the opposite implied ask, so it stays maker-only. LIP gives full credit at or above the reference. The fast-move, trade-through, fair-value and skew guards are unchanged.
- Selection: `LIP_ACTIVITY_WEIGHT`=1. The rank is weighted by floor + (1 - floor) x min(1, 24 h volume / `LIP_ACTIVITY_REF_VOL`=200), with `LIP_ACTIVITY_FLOOR`=0.3. Volume is the larger of GET /markets volume_24h and the trades seen on the socket.
- Fill-sampling group: `LIP_SAMPLE_ENABLE`=1, `LIP_SAMPLE_N`=8 (at most 10) Kalshi markets with >= `LIP_SAMPLE_MIN_TRADES_DAY`=20 public trades in 24 h, at most `LIP_SAMPLE_PER_EVENT`=2 per event. Each is quoted at best bid, `LIP_SAMPLE_SIZE`=10 contracts per side, out of `LIP_SAMPLE_BUDGET_USD`=80 reserved from the Kalshi budget. The group is exempt from the rank (no fill-fraction/adverse penalty) but passes the same exclusions, policy blocks, inventory/risk caps, fill cap, cross guard and fair-value checks. Paper only. Its purpose is real fills and markouts.
- /status: `feed.kalshi_lag` (receive minus exchange time, 60 s window), `feed.clock_skew_trips_n` / `clock_skew_clears_n`, `feed.subscriptions`, `feed.inactive_n`, `clock_skew_pulls_24h`, `fills_by_source` (`kalshi:print` = real, `kalshi:paper_cross`, `*:synthetic`), `fill_sampling`, `checkpoint`. The daily summary has a `checkpoint` line.
